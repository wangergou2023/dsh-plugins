# 失败模式库

这份文件只记**真发生过**的失败：症状 → 根因 → 现在怎么防。新增条目必须带证据（任务 id、文件名或截图）。

---

## 资产层

### F01 狗耳朵少年：定妆把两套形态揉成一张
- 症状：角色定妆出来是「长着狗耳朵的少年」，之后 21 格全都忠实地复刻这个错误角色。
- 根因：`character.look` 是一整句，同时写了本体与人形（"…幻化人形时为 20 岁瘦削少年…"），一整句进 Krea2 → 模型取折中解。
- 现在：`heroFormSpecs()` 命中「兽/骨词 + 人词」就强制拆 beast / human / trans 三张，各带护栏；`character.beast` 独立字段，提示词明令 look 只写人形。
- 证据：`00:00` 早于 `b100`；复现与修复见 `b101`。

### F02 白骨夫人变成"印着骨架花纹的长裙"
- 症状：整片读成民国两人谈恋爱——女人穿墨绿长裙、裙上印骨架图案。
- 根因：同 F01，但这次连分隔词都没命中；单张图里"骨头"被理解成布料图案。
- 现在：人形护栏加「骨相只能出现在皮肤质感上，绝不能做成衣服上的骨头印花」。

### F03 两张定妆图一起喂 → 融合怪物
- 症状：出来"狗头人身 + 骷髅躯干"。
- 根因：参考图生图把每张参考当独立角色，但提示词没点名谁是谁。
- 现在：`refInstruction` 明写「画面里有 N 个完全不同的角色，绝对不要融合成一个：参考图 1 是…参考图 2 是…」。

### F04 过渡形态（半骨半皮）画不出来
- 症状：要"一半骨一半皮"，出来两个并排的人（第二版还多出吉他、铃、鼓凳）。
- 根因：文生图对"一半/一半"没有稳定解。
- 现在：改用 ffmpeg `composeTransHero()` 把本体图左半 + 人形图右半拼成一张（`blend=all_expr='if(lt(X,W/2+10*sin(Y/38)),A,B)'`），确定性，永远不会多出一个人。

### F05 道具每次都不一样
- 症状：同一只表，第 1 镜是黄铜旧表，第 7 镜变银色新表。
- 根因：只有角色定妆当参考图，道具全靠文字描述。
- 现在：道具资产卡（`planProps` / `renderProp` / `propPrompt`），`refsForShot` 排位「角色 → 地点 → 道具」，话术「要的是同一件东西，不是一件同类的」。

## 静帧层

### F06 本体镜拍成人手 / 狗头人身
- 症状：第 04 镜"一只狗 + 一只人手拿怀表"；第 08 镜"狗头人身穿皮夹克"。
- 根因 1：动作写的是"阿哮的**右手**从画面下方伸进来"——本体镜照抄人的动作。
- 根因 2：服装护栏那行「角色全程穿着（…）：阿哮：旧皮夹克和灰T恤」，对本体镜等于命令模型给狗穿皮夹克。
- 现在：`beastAction()` 把手→爪、捡→叼；`beastCamera()` 用动物景别（`four-legged animal anatomy, not standing upright, no human clothing, no human hands`）；服装护栏加 `!beastBody` 条件。

### F07 插入镜（揭示镜）画成人物正脸
- 症状：第 13 镜要"断链 + 香灰 + 刻了一半的辞字"，出来的是男主正脸。
- 根因：人物外形写在提示词最前面，模型优先画人。
- 现在：`insertShot` 分支把场景改写成"画面主体是物件，不是人"，人物降级为焦外手臂，摄影换 `macro close-up on the object, no people in frame`，并跳过情绪/视线/服装护栏。

### F08 过肩镜变成三人镜
- 症状：点名"老周的肩膀在边缘虚焦"后，老周被画两遍。
- 根因：提示词同时说"老周递饼干"（要他出现）和"前景是老周的肩膀"（只要局部），模型当成两个人。
- 现在：前景**不点名**，只写"虚焦的肩膀与后脑剪影"；动作只保留不含对方名字的句子；`otsShot` 阻止重复 push 场景/动作。

### F09 反打两镜拍成同一个人
- 症状：两个正反打镜，女孩穿上了店员的制服。
- 根因：`castOf()` 用 `all.filter(c => names.includes(c.name))` 按角色表顺序返回 → cast[0] 永远是第一号角色。
- 现在：`byName` Map 按 names 顺序取；过肩镜像只喂主角一张参考图（`otsFocus`）。

### F10 手举在胸前像举奖杯 / 手伸出去是空的
- 症状：擦瓶身时两手举到胸口；伸手去拿，手里什么都没有。
- 根因：动作里有手，但没写手和物件的关系。
- 现在：手部护栏——动作命中 `/伸手|递|接过|够|抓|拎|捏|托|扶|按住|拧|扣|拨/` 且有 prop 时追加"这只手正对着{prop}"；擦类动作追加"{prop}放在台面上擦，不要举到胸前或举高"。

## 剧本层

### F11 故事只有一句话
- 症状：面板「生成剧本」给出的"故事"就是一句 logline。
- 根因：面板只渲染 `plan.story.logline`，schema 里也根本没有 scenes。
- 现在：场次体 `scenes[]` + 面板场次卡片 + prompt 规则要求 5–10 场。

### F12 21 镜请求 502
- 症状：210 秒 21 镜直接 502。
- 根因：单次 `maxTokens 4000` 输出 21 镜被截断 → JSON 解析失败。
- 现在：>10 镜走两阶段（剧本骨架 + 分 3 批分镜），每批带时间窗与"已拍镜头清单"防重复。

### F13 第二批开始重复讲同一个故事
- 症状：每批都从"扒土"开始。
- 现在：每批 user 消息里加「这是第 part/total 段」+ 本段场次切片 + 前面已拍镜头清单。

### F14 满分但有三只手
- 症状：100 分那版里出现「折抹布…活鱼还在手里」「双手插围裙兜…旧夹克还在手里」。
- 根因：`assignPropSlots` 的落点句无脑写"{prop}还在手里"，不看这镜的手在干什么。
- 现在：补句四档（穿戴上身 / 搬不动 / 手被占着 / 手是空的）。
- 教训：**拉满分必须读产物本身，不能只看分数**。

### F15 一场戏写成一镜一场
- 症状：21 镜写了 21 场。
- 现在：`mergeScenes` 合并到 ≤10 场 + 机检 `scenes-count`（4–12 场）。

## 流水线层

### F16 改完 index.js 没重载，跑的还是旧代码
- 症状：`/continue` 仍按旧逻辑把 21 镜压回 13 镜。
- 现在：改后端代码后必须 `plugin_manager set_plugin`（disable→enable）再跑；正在跑的任务会被 `reapOrphans` 判成 interrupted，可 `/continue` 续跑。

### F17 面板按钮点了没反应
- 症状：点「导演本」「分镜板」没有任何反应。
- 根因：`window.open` 被 Electron 拦掉且静默失败。
- 现在：`fetch + blob + <a download>`（`downloadFile()` 从 `content-disposition` 取中文名）。

### F18 面板整块空白
- 症状：打开面板一片白。
- 根因：`pollPlanTask` 定义在被 `useEffect(..., [pollPlanTask])` 引用之后 → const 暂时性死区 → 渲染抛错。
- 现在：把 `pollPlanTask` 上移到恢复 effect 之前。

### F19 改完 CSS 不生效
- 症状：改了样式表，界面没变。
- 根因：`ensureStyle()` 是 `if (document.getElementById(...)) return;`，只注入一次。
- 现在：每次比对文本，不一致就替换。

### F20 新写完的镜头动作被通用句覆盖
- 症状：9 镜里 5 镜动作都变成"这一镜只是反应…"。
- 根因：`expandDialogueBeats` 给无台词段写了通用动作，覆盖了原动作。
- 现在：保留 `raw.action`，反应说明只追加到 performance。

## 素材与模型层

### F21 210 秒的歌只出 160 秒
- 症状：整片被压到 160.6 秒。
- 根因：YuE2 单次上限约 108–130 秒，两段拼也常短。
- 现在：拼之前按每段实际时长估算，短超过 5% 就再补一段。
- 坑：第一版去读还没生成的 `song_full.flac` 量长度 → `ENOENT`，任务直接 failed。

### F22 人类角色被塞了 beast，画面凭空多一条狗
- 症状：第 8 镜出现两只狗。
- 根因：模型给普通人也填了 `beast` 字段。
- 现在：schema 文案「只有非人角色才填；是普通人就留空」+ `coerceForm()` 兜底（演员都没有 beast 时，beast/trans/mixed 一律压回 human）。

### F23 视频段把物件举成怪形（伞尖朝上、伞面朝天）
- 症状：《玻璃雨》第 2 镜，首帧里桌上是一把收拢的长柄伞，视频里被举成一团"伞尖朝上、伞面张着"的怪东西，横在画面前景。
- 根因：视频提示词只写了"把伞举到玻璃上、伞尖轻碰玻璃"，没有把**物件的形态**锚在任何东西上；H3 只看到"伞"这个词，就按它自己的先验重画了。
- 现在：`composeVideoPrompt()` 在首帧句后面追加 `${shot.prop}的形状、朝向、颜色全程和 <Picture 1> 里的一样，只改变它在画面里的位置`（`4dd15e6`）。全部用正面陈述，不写"不要变形"。
- 待验证：这条只在《玻璃雨》跑完后才可能验证（改提示词时任务已在渲染中）。

## 一条通用规律

**模型对否定不敏感，对词根敏感。** 写"不要赤膊""不要泪"时，"赤膊/泪"照样被激活。
改法（三改法之一）：把禁令改写成**主体式**正面陈述——"衣领扣到第二颗、袖口到手腕""他在忍，眼圈发红但没有掉下来"。
